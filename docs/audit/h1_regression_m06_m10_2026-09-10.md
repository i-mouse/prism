# Audit: H1 Regression for REFLEX-M06 and REACT-M10

## Q1: Exact Claims and Backing Evidence

**REFLEX-M06**
- **Verbatim Text**: "Table 3 shows an inferior 52% vs 60% (baseline) accuracy, which suggests that the agent is unable to determine if the current implementation is correct without unit tests."
- **Backing Evidence**: Section 4.3 and Table 3.

**REACT-M10**
- **Verbatim Text**: "While two ReAct + CoT-SC methods are advantageous at one task each, they both significantly and consistently outperform CoT-SC across different number of samples, reaching CoT-SC performance with 21 samples using merely 3-5 samples."
- **Backing Evidence**: Section 3.3 and Figure 2.

## Q2: Confirmation of Absence vs Presence

**REFLEX-M06 is genuinely absent** from the current fixture (`arxiv-2303.11366v4.json`). The extractor entirely missed this ablation result. Instead, nearby claims extracted from Section 4.3 include:
- Claim 2: *"For example, Reflexion achieves a 91% pass@1 accuracy on the HumanEval coding benchmark, surpassing the previous state-of-the-art GPT-4 that achieves 80%."*
- Claim 11: *"We show that Reflexion achieves improvements over strong baselines across several tasks, and achieves state-of-the-art results on various code generation benchmarks."*
- Claim 15: *"Reflexion outperforms all baseline accuracies and sets new state-of-the-art standards on all benchmarks for Python and Rust except for MBPP Python 1."*

**REACT-M10 is NOT absent**. It actually **was** extracted in the current fixture (`arxiv-2210.03629v3.json`) as Claim 15:
- Claim 15: *"While two ReAct + CoT-SC methods are advantageous at one task each, they both signi\ufb01cantly and consistently outperform CoT-SC across different number of samples, reaching CoT-SC performance with 21 samples using merely 3-5 samples."*

The reason it appears missing is a **matcher failure**, likely due to the `\ufb01` (fi) ligature in "signi\ufb01cantly". The downstream evaluation script failed to match Claim 15 to the `REACT-M10` expected ID, returning `actual_index: null`. Ironically, before the H1 fix, `REACT-M10` was *not* extracted correctly, but the old matcher falsely linked it to an unrelated claim (Claim 7: "the best prompting method... are ReAct->CoT-SC and CoT-SC->ReAct").

## Q3: Hypothesis Check — Prompt Instructions

The post-H1 extractor prompt (`extract_claims_system.md`) heavily skews the model towards the beginning of the paper, directly causing the crowding-out of later empirical claims like REFLEX-M06:
1. **Strict Ordering Mandate**: *"Before scanning mid-paper sections, you MUST first walk through every sentence of the Abstract and Introduction... Only after every Abstract and Introduction claim has been captured should you scan Results, Ablations, and Discussion for additional claims."*
2. **Claim Count Ceilings**: The prompt sets a soft target: *"Papers typically yield 15-30 claims... Extracting more than 35 means you are including plain implementation details"*.
3. **Few-Shot Skew**: The `extract_claims_fewshot.json` examples are now heavily skewed toward positioning claims from the abstract/intro (6 out of 7 positive examples). The model learns to focus its token budget there.

## Q4: Total Claim Counts (Trade-off vs Drop)

This is a **positioning-vs-empirical trade-off (crowding out)**, not a genuine drop in total output capacity. The model is extracting *more* claims than before, but exhausting its self-imposed limit on the intro before reaching deep ablation tables.
- **Pre-H1 Total Claims**: 14 (Reflexion) and 14 (ReAct).
- **Post-H1 Total Claims**: 16 (Reflexion) and 19 (ReAct).

## Q5: Proposed Minimal Fix

1. **Raise the claim count ceiling**: Update `extract_claims_system.md` to say *"Papers typically yield 25-45 claims"* to prevent the model from stopping early once it finishes the heavily-mined Abstract/Introduction.
2. **Balance the few-shot examples**: Add 1-2 explicit few-shot examples demonstrating the extraction of detailed empirical claims from late-paper Ablation sections and Tables (similar to REFLEX-M06) to remind the model it must continue extracting numeric data deep in the paper.
3. **Fix the Matcher Ligature Bug**: Normalize unicode ligatures (like `\ufb01` -> `fi`) in the downstream evaluation script so that perfectly extracted claims like REACT-M10 aren't erroneously marked as missing.
